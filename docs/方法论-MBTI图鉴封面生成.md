# 方法论：MBTI 图鉴封面生成

> 将一部作品的全部角色剧照 + MBTI 类型信息，合成为一张九宫格群像封面 PNG 图片。

---

## 一、任务定义

**输入**：

| 材料 | 格式 | 说明 |
|------|------|------|
| MBTI 类型表 | Markdown | 角色名 + 四字母类型 + 功能栈，每行一个角色 |
| 角色剧照 | jpg/png/webp | 每张图片文件名 = 角色名（如 `樊长玉.jpg`） |
| 封面 HTML 模板 | HTML | `templates/图鉴封面模板.html` |

**输出**：
- 一张 PNG 封面图片（540×960 CSS 像素，实际输出 1080×1920，2x 分辨率）
- 存放于指定输出目录

**与"角色海报生成"的区别**：
- 角色海报 = 每个角色一张详情长图（含分析文本、台词、功能栈解读）
- 图鉴封面 = 所有角色合成一张九宫格群像图（仅含角色名 + MBTI 类型）

---

## 二、前置条件

### 2.1 环境依赖

```
Node.js >= 18
Python 3 + opencv-python-headless
npm 包：playwright
```

### 2.2 材料格式规范

#### MBTI 类型表（`.md`）

每行一个角色，格式为：

```
N）角色名：MBTI类型（功能栈）
```

示例：

```
1）樊长玉：ESFP（Se-Fi-Te-Ni）
2）谢征：INTJ（Ni-Te-Fi-Se）
```

关键解析锚点：
- `N）` 作为编号标记
- `：` 后为 MBTI 四字母类型
- `（）` 内为功能栈

#### 角色剧照

- 每个角色一张图片
- 文件名 = 角色名 + 扩展名（如 `谢征.jpg`），角色名必须与类型表中完全一致
- 支持 `.jpg`、`.jpeg`、`.png`、`.webp`
- 图片应为角色的近景或中景剧照，确保人脸清晰可见

---

## 三、执行步骤

### Step 1：解析 MBTI 类型表

从 Markdown 文件中提取所有角色的：
- 角色名
- MBTI 四字母类型
- 出场顺序编号

输出为有序列表，后续步骤按此列表顺序填充九宫格。

### Step 2：确认角色排列顺序

**九宫格的排列顺序直接影响视觉效果。** 默认按类型表中的编号顺序，但需根据以下原则调整：

- 若用户指定了顺序调整（如"A 和 B 换个位置"），按用户要求执行
- 若无特殊要求，按类型表原始顺序排列

将最终顺序记录下来，作为后续生成 HTML 的依据。

### Step 3：运行人脸检测

```bash
python3 scripts/detect-faces.py <剧照目录路径>
```

脚本输出 JSON，格式为：

```json
{
  "角色名": { "x_pct": 50.0, "y_pct": 35.0 },
  ...
}
```

**此步骤不可跳过。** 详见底层规则 1。

### Step 4：生成填充内容的 HTML 文件

基于封面模板 HTML，将以下内容填入：

1. **每个 `.still-card` 中的 `<img>`**：
   - `src` 属性：使用绝对路径（`file://` 协议），指向对应角色的剧照
   - `style` 属性：添加 `object-position: {x_pct}% {y_pct}%`，值来自 Step 3 的人脸检测结果
   - `alt` 属性：角色名

2. **每个 `.label` 中的文字**：
   - `.cn`：角色名
   - `.mbti`：MBTI 四字母类型

3. **排列顺序**：按 Step 2 确定的顺序，从左到右、从上到下填充九宫格

将生成的 HTML 保存到 `scripts/temp-posters/` 目录下，文件名建议为 `{作品名}封面.html`。

### Step 5：使用 Playwright 截图为 PNG

编写或调用 Node.js 脚本，使用 Playwright 完成截图：

```javascript
const browser = await chromium.launch();
const context = await browser.newContext({
  viewport: { width: 580, height: 1040 },
  deviceScaleFactor: 2,
});
const page = await context.newPage();
await page.goto(`file://${htmlPath}`, { waitUntil: 'networkidle' });
await page.waitForTimeout(1000);

const poster = await page.$('.poster-container');
await poster.screenshot({ path: outputPath, type: 'png' });
await browser.close();
```

关键参数说明：
- `viewport`：宽度 580 是为了给 540px 的 poster-container 留出两侧空白，避免截图边缘被裁
- `deviceScaleFactor: 2`：输出 2x 分辨率，确保在 Retina 屏上清晰
- `waitForTimeout(1000)`：等待图片和字体加载完成
- 截图目标是 `.poster-container` 元素而非全页面，避免截入 body 背景

### Step 6：目视校验

打开生成的 PNG，逐格检查：

| 检查项 | 具体标准 |
|--------|----------|
| 人脸完整性 | 每个角色的脸在其格子内完整可见，未被裁切出画面 |
| 人脸居中性 | 脸部大致处于格子的视觉中心区域，不偏到边缘 |
| 角色名正确 | 每个格子下方的毛玻璃标签中，角色名与剧照一致 |
| MBTI 类型正确 | 每个标签中的 MBTI 类型与类型表一致 |
| 排列顺序 | 九宫格从左到右、从上到下的顺序与 Step 2 确定的一致 |
| 图片质量 | 剧照清晰，无拉伸、无黑边、无加载失败的空白格 |
| 标签可读性 | 角色名和 MBTI 类型文字清晰可读，未被遮挡 |

## 四、产出要求

### 4.1 封面结构

```
┌──────────────────────────┐
│  ┌────┬────┬────┐        │
│  │角色1│角色2│角色3│        │  ← 3×3 九宫格，无间隙
│  ├────┼────┼────┤        │
│  │角色4│角色5│角色6│        │  ← 每格包含：剧照 + 毛玻璃标签
│  ├────┼────┼────┤        │
│  │角色7│角色8│角色9│        │  ← 标签内容：角色名 + MBTI 类型
│  └────┴────┴────┘        │
│  [胶片颗粒感叠加层]       │  ← 全局覆盖，增加质感
└──────────────────────────┘
```

### 4.2 单格结构

每个格子包含两层：

1. **底层：角色剧照**
   - `object-fit: cover` 填满格子
   - `object-position` 由人脸检测结果决定
   - 统一滤镜：`saturate(0.88) contrast(1.02) brightness(0.96)`，营造统一色调

2. **上层：毛玻璃标签**
   - 位于格子底部，左右各留 10px 边距
   - 背景：半透明渐变 + `backdrop-filter: blur(8px)`
   - 圆角 12px，带 1px 半透明白色边框
   - 角色名：20px 宋体/衬线字体，加粗，白色
   - MBTI 类型：13px 无衬线字体，加粗，暖米色 `#f2e1cc`

### 4.3 视觉规格

| 参数 | 值 |
|------|-----|
| 海报尺寸（CSS） | 540px × 960px（9:16） |
| 输出尺寸（像素） | 1080px × 1920px |
| 截图分辨率 | deviceScaleFactor: 2 |
| 格子数量 | 3×3 = 9 格 |
| 格子间隙 | 0（无缝拼接） |
| 人脸定位方式 | OpenCV Haar 级联检测 → CSS `object-position` |
| 输出格式 | PNG |
| 全局色调 | 微降饱和度 + 微增对比度 + 微降亮度，呈现电影胶片感 |

### 4.4 文件命名

- 输出 PNG：`{作品名}封面.png`（如 `逐玉封面.png`）
- 临时 HTML：`scripts/temp-posters/{作品名}封面.html`

## 五、底层规则

### 规则 1：人脸检测不可跳过，不可用固定 object-position 代替

**原理**：九宫格的每个格子面积很小（仅 180×320 CSS 像素），`object-fit: cover` 裁切比例极大。如果人脸不在裁切后的可见区域内，角色将完全不可辨认——这在封面图中是致命的。

**实现方式**：
- 调用 `detect-faces.py`，使用 OpenCV Haar 级联分类器（正脸 + 侧脸 + 水平翻转）检测人脸中心
- 将人脸中心的百分比坐标赋给 `<img>` 的 `style="object-position: X% Y%"`
- 检测失败时使用安全默认值 `50% 35%`

**常见错误**：直接在 CSS 中写 `object-position: center`——这会导致偏脸构图或脸在画面边缘的剧照，人脸被裁出画面。

### 规则 2：图片路径必须使用绝对路径

**原理**：Playwright 通过 `file://` 协议加载本地 HTML。在 `file://` 协议下，相对路径的解析行为因系统和浏览器实现而异，极易导致图片加载失败（表现为黑色空格）。

**实现方式**：
- HTML 中所有 `<img src="...">` 使用完整的绝对文件路径
- 在脚本中通过 `path.resolve()` 生成绝对路径

### 规则 3：截图目标是 `.poster-container` 元素，不是整个页面

**原理**：HTML 模板的 `body` 带有深色背景和 flex 居中布局，用于在浏览器中预览时提供视觉衬底。如果截整个页面，会截入 body 的背景色和留白，导致输出尺寸不可控。

**实现方式**：
```javascript
const poster = await page.$('.poster-container');
await poster.screenshot({ path: outputPath, type: 'png' });
```

### 规则 4：格子数量必须与角色数量一致

**原理**：模板是 3×3 九宫格，设计用于 9 个角色。如果角色数量不是 9 个：
- 少于 9 个：会出现黑色空格，破坏整体美感
- 多于 9 个：超出的角色不会显示

**处理方式**：
- 如果角色恰好是 9 个，直接使用九宫格模板
- 如果不是 9 个，需要调整模板的 `grid-template-columns` 和 `grid-template-rows`，或与用户确认是否裁剪角色列表

### 规则 5：统一滤镜确保视觉一致性

**原理**：不同剧照的拍摄条件不同（光线、色温、对比度），直接拼在一起会显得杂乱。统一滤镜的作用是将所有图片拉到同一个色调空间。

**当前滤镜参数**：`filter: saturate(0.88) contrast(1.02) brightness(0.96)`
- 微降饱和度：去掉过于鲜艳的颜色，趋向胶片质感
- 微增对比度：增加画面层次
- 微降亮度：配合深色毛玻璃标签的可读性

**注意**：不要大幅调整这些参数。小幅度调整（±0.05 以内）足够，大幅调整会导致画面失真。

## 六、经验总结

### 6.1 人脸检测

- **Haar 级联器必须多策略组合**：单独用 `haarcascade_frontalface_default.xml` 只能覆盖正面人脸。古装剧照中侧脸、仰角、暗光场景很常见，必须同时加载 `haarcascade_frontalface_alt2.xml`（正脸备选）+ `haarcascade_profileface.xml`（侧脸）+ 水平翻转检测（朝右的侧脸），配合多组 `scaleFactor`（1.1 和 1.05）和 `minNeighbors`（3 和 2）参数扫描
- **取面积最大的检测框**：多策略扫描会产生大量候选框（同一张图可能 10-60 个），按面积降序排列取第一个——角色剧照通常只有一个主体人物，最大的框就是主角的脸
- **安全默认值用 `50% 35%` 而非 `50% 50%`**：人像照片的脸通常在画面上方 1/3 处，`50% 50%` 会把脸定位得偏低

### 6.2 九宫格的裁切特性

- 九宫格每格的宽高比约为 **1:1.78**（180×320），接近 9:16。但大多数剧照是 16:9 或 3:2 的横向构图，裁切量很大
- **横向构图的剧照**：左右会被大量裁切，人脸检测结果中的 `x_pct` 至关重要——它决定了左右裁切的偏移方向
- **竖向构图的剧照**：上下裁切较少，`y_pct` 的影响相对较小
- **双人或多人构图的剧照**：如果原图中有多个人物，人脸检测会定位到面积最大的那个脸，但格子很小，通常只能清晰展示一个人——应尽量选用单人剧照作为素材

### 6.3 Playwright 截图

- **`waitForTimeout(1000)` 是必要的**：虽然 `waitUntil: 'networkidle'` 会等待网络请求完成，但本地 `file://` 图片的加载不一定触发网络事件。额外等待 1 秒确保所有图片渲染完成
- **viewport 宽度设为 580 而非 540**：给 poster-container 两侧各留 20px 余量，避免 flex 居中时元素紧贴视口边缘导致的亚像素渲染问题
- **`deviceScaleFactor: 2` 影响实际输出尺寸**：540px CSS 宽度在 2x 下输出 1080px 物理像素，这是社交媒体发布的标准清晰度

### 6.4 HTML 模板维护

- **模板文件中使用占位内容**：模板中的角色名、MBTI 类型、图片路径都是占位符（如"达西""INTJ"），生成脚本负责替换为实际内容。不要直接在模板文件上修改内容
- **临时 HTML 保留在 `scripts/temp-posters/`**：方便调试时在浏览器中直接打开检查排版效果，不必每次都走 Playwright 截图流程
- **模板的 CSS 样式不应在生成脚本中覆盖**：如果需要调整视觉效果，修改模板文件本身，而非在脚本中注入内联样式（人脸定位的 `object-position` 除外，它本身就是动态值）

## 七、质量校验清单

### 产出物校验

- [ ] 九宫格所有 9 个格子均有剧照显示，无黑色空格
- [ ] 每个格子中角色的脸完整可见，未被裁切出画面
- [ ] 每个格子的毛玻璃标签中，角色名与剧照中的人物一致
- [ ] 每个标签的 MBTI 类型与类型表一致
- [ ] 九宫格排列顺序与确认的顺序一致
- [ ] 所有格子的色调统一（无某一格明显偏亮/偏暗/偏色）
- [ ] 图片整体清晰，无模糊或像素化
- [ ] 毛玻璃标签的文字清晰可读，与背景有足够对比度

### 流程校验

- [ ] 人脸检测脚本已执行，且所有角色均有检测结果（含 fallback 默认值）
- [ ] HTML 中所有 `<img>` 均使用绝对路径
- [ ] HTML 中每个 `<img>` 的 `object-position` 均已设置为人脸检测结果值
- [ ] 生成脚本使用 `deviceScaleFactor: 2`
- [ ] 截图目标为 `.poster-container` 元素
